# Cuestionario — Módulo de Facturación

**Depósito Emmanuel**
Para completar con la propietaria (y, si se puede, con el contador presente).

**Por qué este cuestionario:** hoy el negocio calcula el impuesto (IVA) a mano
para pasárselo al contador, lo que toma tiempo y puede generar errores. La idea
del módulo de facturación es que, con solo registrar la venta, el sistema
calcule el impuesto automáticamente y genere el reporte que el contador necesita.
Para lograrlo necesitamos entender bien cómo factura hoy.

> Cada pregunta indica entre paréntesis el tipo de campo en Google Forms:
> *(corta)*, *(párrafo)*, *(opción múltiple)*, *(casillas)*, *(archivo)*.
> El script `crear_formulario_facturacion.gs` genera el formulario completo.

### Notas para el equipo (no van en el formulario)

- **Régimen** define el motor de cálculo:
  - *Pequeño Contribuyente*: impuesto = 5% del total facturado del período. La factura
    lleva la frase "No genera derecho a crédito fiscal". No se descuenta IVA de compras.
  - *Régimen General*: IVA débito = 12% de ventas gravadas; IVA crédito = 12% de compras
    con factura; a pagar = débito − crédito. Requiere que el módulo de compras ya guarde
    el IVA de cada factura de proveedor (hoy guarda `precio_unitario`; habría que separar
    base e IVA o marcar la compra como "con crédito fiscal").
- **FEL**: si el cliente quiere emisión automática, hay que evaluar certificadores
  (Guatefacturas, Infile, Digifact, etc.) y su costo/API. Alternativa de bajo costo:
  el módulo prepara el DTE y la propietaria lo emite en la app gratuita de SAT.
- La tabla `venta` ya tiene columnas para esto (`descuento_monto`, `metodo_pago`, etc.)
  pero **no** hay columnas de NIT del receptor, número de DTE, ni desglose de impuesto.
  Eso se define después de las respuestas.
- Roles: el módulo se habilita para **Admin** y para un nuevo rol **Contador**
  (solo consulta de facturas y reportes). Cajero y Repartidor no lo ven.
